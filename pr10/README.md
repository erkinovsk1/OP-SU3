## 1. Ручной перевод контрольных адресов
Параметры системы: размер страницы `PAGE_SIZE = 1024 Б` (1 КБ).  
Таблица страниц: `0 → 5`, `1 → 2`, `2 → 7`, `3 → 0`.

1. **Адрес `1200`:**
   * $\text{page} = 1200 \div 1024 = 1$
   * $\text{offset} = 1200 \bmod 1024 = 176$
   * Страница `1` отображается в кадр `2`.
   * $\text{phys\_addr} = 2 \times 1024 + 176 = \mathbf{2224}$.

2. **Адрес `3100`:**
   * $\text{page} = 3100 \div 1024 = 3$
   * $\text{offset} = 3100 \bmod 1024 = 28$
   * Страница `3` отображается в кадр `0`.
   * $\text{phys\_addr} = 0 \times 1024 + 28 = \mathbf{28}$.

3. **Адрес `5000`:**
   * $\text{page} = 5000 \div 1024 = 4$
   * $\text{offset} = 5000 \bmod 1024 = 904$
   * Запись для страницы `4` отсутствует $\rightarrow$ **ошибка «страница отсутствует» (Page Fault)**.

## 2. Ответ на задание № 4
**Почему размер страницы выбирают степенью двойки (что это даёт при вычислении номера и смещения)?**  
Если размер страницы равен $2^k$ байт (например, $1024 = 2^{10}$ или $4096 = 2^{12}$), процессору и блоку управления памятью (MMU) не нужно выполнять медленные аппаратные операции целочисленного деления (`/`) и взятия остатка (`%`). В двоичном представлении $n$-битного логического адреса:
* **Младшие $k$ бит** напрямую представляют собой **смещение (`offset`)** (получаются побитовым «И» с маской `addr & (PAGE_SIZE - 1)`).
* **Старшие $n - k$ бит** напрямую задают **номер страницы (`page`)** (получаются обычным побитовым сдвигом вправо `addr >> k`).  
Формирование физического адреса также сводится к простой конкатенации битов номера кадра и смещения (`(frame << k) | offset`), что выполняется за один такт на уровне проводов в аппаратуре.

## 3. Ответы на контрольные вопросы

1. **Почему без TLB страничная организация замедлила бы каждое обращение к памяти вдвое и более?**  
   Поскольку таблица страниц сама хранится в оперативной памяти, для каждого обращения программы к данным или инструкциям процессору пришлось бы совершать **два обращения к ОЗУ**: сначала прочитать номер кадра из таблицы страниц (по регистру `PTBR`), а затем обратиться по вычисленному физическому адресу к самим данным. При многоуровневых таблицах страниц (например, 4-уровневой в x86-64) потребовалось бы **5 обращений к памяти вместо 1**, что замедлило бы работу в 5 раз. Буфер ассоциативной трансляции (TLB) кэширует недавние переводы внутри процессора.

2. **Что хранится в записи таблицы страниц (PTE) помимо номера кадра?**  
   Помимо номера физического кадра (PFN), запись таблицы страниц содержит служебные управляющие флаги:
   * **Бит присутствия (`Present / Valid`)** — находится ли страница сейчас в ОЗУ или выгружена на диск;
   * **Биты прав доступа (`Read / Write / Execute`, `User / Supervisor`)** — защита памяти от записи в код или доступа из пространства пользователя к памяти ядра;
   * **Бит обращения (`Accessed / Reference`)** — выставляется аппаратно при чтении/записи, используется алгоритмами замещения страниц (например, Clock/LRU);
   * **Бит модификации (`Dirty`)** — показывает, изменялась ли страница после загрузки с диска (нужно ли записывать её обратно при вытеснении);
   * **Флаги кэширования** (например, отключение кэша для областей ввода-вывода MMIO).
